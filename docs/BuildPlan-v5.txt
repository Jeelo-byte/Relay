A · Audit — what was wrong or missing in v4

🔴 Blocker = the build fails or the demo lies without a fix. 🟠 Major = real bugs or rework. 🟡 Minor = polish or honesty. Each row points to where v5 fixes it.


#FindingFix in v5

🔴 A1Synapse + bbctl cannot be combined. Beeper's bridge manager states it cannot be used with any other homeserver such as a self-hosted Synapse — it only connects bridges to beeper.com. v4 lists both.ADR-01: self-hosted Synapse + mautrix bridges via Docker Compose. bbctl moved to v2.

🔴 A2Matrix E2EE is unaccounted for. If you use Beeper with self-hosted bridges, end-to-bridge encryption means Beeper's servers never see messages — which also means every Relay client must implement Olm/Megolm, device verification and key backup in Swift and in the browser. Not in the stack, not in the timeline.ADR-01 avoids it for the hackathon (unencrypted rooms on your own Synapse, which runs on your own Mac). Beeper path documented as v2 with matrix-rust-sdk.

🔴 A3Demo contradiction: “Wi-Fi off … a live message arrives via Matrix.” Offline devices receive nothing.§N: receive online → Airplane Mode on → extract locally → Airplane Mode off → sync.

🔴 A4“Proposed” means two different things: an AI suggestion waiting for your review, and an offer in the chat the other person hasn't accepted. One field can't hold both.§C two-axis model: review_state × lifecycle.

🔴 A5No extraction ownership. Mac, iPad, iPhone and web all see the same message and all run extraction → duplicate agreements, double cloud spend, races. “Dedupe after decrypt” runs too late.§J keyed-HMAC leases with device priority; suggested agreements sync too.

🔴 A6No account authentication. A pseudonymous UUID doesn't prove anything. Nothing says how a new device logs in to fetch its wrapped DEK.§E/§F: Argon2id output split by HKDF into KEK + auth key; server stores a verifier; bearer sessions.

🔴 A7Scope vs. clock. If submission is Sun 12:00, about 21 hours remain for four clients, crypto, bridges, local LLM and sync.§M hackathon cut line + go/no-go gates; full spec kept for after.

🔴 A8Source trail breaks off-device. Messages are never in Neon, so the web client (or a device that hasn't backfilled that room) cannot show the quote behind a term.§D: evidence quotes (≤280 chars) live inside the encrypted agreement blob.

🔴 A9Only confirmed agreements sync (v4 pipeline step 7→9). Unconfirmed suggestions stay local, so every other device re-extracts them.§J: suggested + dismissed agreements sync as ciphertext too.

🟠 A10Gemma 3 is a generation behind. Gemma 4 shipped in E2B, E4B, 26B A4B and 31B sizes, under Apache 2.0 (Gemma 3 used the Gemma Terms of Use). 4-bit MLX builds such as mlx-community/gemma-4-e2b-it-4bit exist and run through mlx-swift-lm.ADR-02: Gemma 4 E2B / E4B. Pin revision.

🟠 A11Background GPU assumptions are wrong. Background GPU access is only available on iPads; on iPhone it isn't available. On iOS 26, in-flight Metal work is aborted with “accessRevoked” on backgrounding and can crash the host app. v4 says “batches via Background Tasks”.§I: foreground inference, cancel at token boundary on scenePhase change, iPad-only BGContinuedProcessingTask with .gpu.

🟠 A12“DEK in Secure Enclave” — the Secure Enclave holds P-256 private keys, not AES keys.§E: DEK in Keychain with biometric access control, optionally wrapped by an SE P-256 key.

🟠 A13NSFileProtectionComplete makes the DB unreadable while locked — background sync, notifications and catch-up all fail.§E: completeUntilFirstUserAuthentication for DB; app-level lock screen instead.

🟠 A14Argon2id isn't in CryptoKit or WebCrypto.§E: libsodium on both sides, fixed params, shared test vectors.

🟠 A15No AEAD binding / rollback protection. Neon could swap two blobs or serve an old version and clients would accept it.§E AAD = account|row|version; client high-water marks.

🟠 A16“Redact PII before cloud” destroys extraction — parties and amounts are the payload.§H reversible pseudonymisation (P1, P2, [PHONE1]) with the map kept on-device.

🟠 A17Prompt injection from chat text not addressed.§H data framing, no tools, schema-only output, quote verification.

🟠 A18Hallucinated evidence not checked mechanically.§H validator: message ID must be in window and quote must be an exact (normalised) substring.

🟠 A19“Original timezone” doesn't exist — Matrix events carry no sender timezone.§H: anchor in user's tz at extraction; store tz_assumed; date-only deadlines are floating dates.

🟠 A20Date resolution by LLM is non-deterministic and would differ across Swift/TS.§H: LLM copies raw text; one deterministic TS resolver runs on web and inside JavaScriptCore on Apple.

🟠 A21Money — no integer storage, no per-currency totals, no rule for split bills.§D minor units + ISO 4217; derived amounts flagged and excluded from totals until accepted.

🟠 A22Web IndexedDB cache would hold plaintext.§J: IndexedDB stores ciphertext only; plaintext in memory.

🟠 A23Who is “you” in a bridged room isn't defined.§G double puppeting → is_self.

🟠 A24Reaching Synapse on a Mac from iPad/iPhone/web off-LAN, and iOS ATS requires HTTPS.§G Tailscale + HTTPS cert; web via Tailscale Funnel or hosted proxy.

🟠 A25Conflict resolution by timestamps breaks under clock skew.§J server-assigned seq + optimistic base_version.

🟠 A26Agreement types missing: recurring, conditional, partial payment, cancellation, counter-offer, completion.§C/§D obligations + timeline event types.

🟠 A27Foundation Models can refuse content with guardrail errors, and availability has several states.§I handled error matrix.

🟠 A28MLX doesn't accelerate in the iOS Simulator; agents can't test inference there.§L LLMEngine protocol + MockLLM + real-device gate.

🟠 A29No contracts, fixtures, evals or definition of done — the biggest gap for a swarm.Parts D–L, T.

🟠 A30No UI state spec (empty / loading / locked / offline / error), no motion tokens, no copy deck.Part UI.

🟡 A31Bridge logins have prerequisites: Telegram needs an API id/hash, WhatsApp needs a linked phone, Discord user-account bridging carries ToS risk.§G with consenting team accounts.

🟡 A32Matrix push (Sygnal + APNs) is a project of its own.Out of scope; local notifications scheduled from due dates.

🟡 A33iOS caps pending local notifications (64).Schedule nearest 50.

🟡 A34Local notifications don't transit APNs — the real exposure is the lock screen.Generic text by default; “show details” setting off.

🟡 A35Ciphertext length leaks content size.Pad to buckets (§E).

🟡 A36No data export / account deletion / login rate limiting / cloud-LLM cost cap.§F.

🟡 A37App-switcher snapshots, clipboard, logs and crash reports can leak terms.§K privacy rows.

🟡 A38Model weights in Caches can be purged; HF repos can be gated or moved.§I Application Support + backup exclusion + pinned revision + mirror.

C · Product rules & the two-axis status model

If a feature doesn't help create, prove, update or act on an agreement, it isn't P0. Agreements are a shared-understanding view — not a legal contract, not legal advice.

Axis 1 — review_state (you vs. the AI)

ValueMeaningShown asTransitions

suggestedAI found it; you haven't looked“Suggested” section, dashed card border, sparkle icon→ accepted (Accept / Edit+Save) · → dismissed

acceptedYou confirmed it (or created it manually)Normal card→ dismissed only via Delete (writes tombstone)

dismissedYou said “not an agreement”Hidden; listed in Settings › Dismissed (undo)→ suggested (Undo within list)


Axis 2 — lifecycle (the real-world agreement)

ValueMeaningChip

offeredSomeone proposed/asked; the other side hasn't clearly acceptedOffered

agreedBoth sides acceptedAgreed

fulfilledAll obligations doneDone

cancelledCalled offCancelled

disputedParties' later messages contradict each otherDisputed


Derived (never stored): Overdue = lifecycle ∈ {offered, agreed} ∧ an open obligation's due end < now. Due soon = due within 48 h. Waiting on you = an open obligation where obligor is self. Waiting on them = obligee is self, obligor is someone else.

Rules every agent enforces


The AI never changes an accepted agreement. It appends a timeline event with review_state:"suggested"; the user applies or rejects it. The AI may revise its own still-suggested agreement (logged in timeline).

No term without evidence. Every amount, date, place and party on an AI agreement cites ≥1 evidence item. Missing = “Not stated”.

Totals count only accepted, open obligations with a stated amount, grouped per currency, never converted. Derived amounts (split bills) count only after the user accepts them.

Manual mode is complete: create, edit, delete, mark done with zero LLM calls.

Only opted-in rooms the user is in are read. Opt-in defaults to off for every room.

Nothing is shared with other participants. No auto-send, ever.

Dismissed is sticky: event IDs covered by a dismissed suggestion are never re-suggested unless a new message changes them.

D3 · Display formatting rules


Money: Intl.NumberFormat / FormatStyle.Currency with the stored currency, device locale. Never infer currency from locale at display.

E · Crypto spec (exact)

Every parameter is fixed. Swift and TS must produce byte-identical output for the test vectors in packages/crypto-vectors.json.

E1 · Key hierarchy

passphrase  ──NFKC normalise (no trim)──► UTF-8 bytes
salt        = 16 random bytes (stored clear in Neon)
master      = Argon2id(passphrase, salt, opslimit=3, memlimit=64 MiB, out=32)   // libsodium crypto_pwhash ALG_ARGON2ID13
KEK         = HKDF-SHA256(ikm=master, salt="", info="relay/v1/kek",  L=32)
auth_key    = HKDF-SHA256(ikm=master, salt="", info="relay/v1/auth", L=32)  // sent to server at login
verifier    = SHA-256(auth_key)                                          // server stores this only

DEK         = 32 random bytes per account per key_version
blob_key    = HKDF(DEK, info="relay/v1/blob")
db_key      = HKDF(DEK, info="relay/v1/sqlcipher")
lease_key   = HKDF(DEK, info="relay/v1/lease-hmac")
token_key   = HKDF(DEK, info="relay/v1/local-secrets")   // wraps Matrix access token on web

recovery_secret = 39 random Crockford base32 chars (195 bits) + 1 Crockford mod-37 check char
                  → shown as 8 groups of 5 (e.g. 7KQ2M-…); input normalised: uppercase, O→0, I/L→1, spaces/dashes removed
recovery_KEK    = HKDF(ikm = UTF-8 of the 39 data chars, info="relay/v1/recovery-kek")   // no Argon2: high-entropy

E2 · Wrapping

wrapped_dek = AES-256-GCM(key=KEK | recovery_KEK, nonce=12 random,
                          aad="relay/v1/wrap|{account_id}|{key_version}|{wrap_type}",
                          plaintext=DEK)
stored as: nonce(12) || ciphertext(32) || tag(16)

E3 · Blob envelope

plaintext_json → UTF-8 → pad: append 0x80 then 0x00… to the next bucket
  buckets: 512, 1K, 2K, 4K, 8K, 16K, 32K, 64K
nonce = 12 random bytes (never reused; ~2^32 blob limit per DEK is far above need)
aad   = "relay/v1/blob|{account_id}|{row_id}|{version}|{key_version}"
ct    = AES-256-GCM(blob_key, nonce, aad, padded)
envelope (bytes) = 0x01 (format) || key_version (uint32 BE) || nonce(12) || ct||tag
transport: base64url (no padding) in JSON


version in AAD = the version the client is writing (base_version + 1). Server can't move a blob to another row, account or version without the tag failing.

Rollback: client stores HighWater[row_id] = max version seen; any pulled blob with lower version is ignored and logged as a sync issue.

Decrypt failure: quarantine the row (keep ciphertext, don't overwrite), increment Settings › Sync issues counter, continue.


E4 · Device storage

PlatformDEK at restLocal DBUnlock

iOS / iPadOSKeychain generic password, kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly, synchronizable = false. Separate access-control item with .biometryCurrentSet gates the UI unlock.SQLCipher keyed with db_key (or Data Protection completeUntilFirstUserAuthentication fallback, ADR-05). Why AfterFirstUnlock and not WhenUnlocked/Complete: the app must sync and schedule notifications while the screen is locked. The app's own lock screen + biometric gate protects the UI.

E5 · Flows


Sign-up: choose handle (3–32 chars [a-z0-9_], not an email — client rejects “@”) + passphrase (≥ 12 chars, zxcvbn score ≥ 3) → derive → generate DEK + recovery secret → wraps → POST /v1/accounts → show recovery code → user retypes groups 2 and 7 → continue.

Login new device: GET /v1/prelogin?handle → salt+params → derive → POST /v1/sessions with auth_key → receives wraps → unwrap DEK with KEK → store per E4.

Recovery: enter code → recovery_KEK unwraps recovery wrap → force new passphrase → re-wrap DEK with new KEK + new verifier → PUT /v1/accounts/credentials.

Passphrase change: needs old auth_key; re-wrap DEK only (no blob re-encryption).

Rotation (v1, manual): new DEK (key_version+1) → re-encrypt all blobs locally → upload → new wraps → delete old wraps. Old key kept in memory until done. Devices seeing an unknown key_version prompt for passphrase.

Device removal: revoke session server-side; the removed device can still read what it already downloaded — UI says so and offers “Rotate keys”.


Unrecoverable by design — shown at sign-up and on the recovery-code screen: “If you lose your passphrase, all your devices, and this recovery code, nobody — including us — can recover your agreements.”
Crypto vectors file committed; Swift (XCTest) and TS (vitest) both pass it: Argon2id, HKDF labels, wrap, blob envelope with fixed nonce, padding
Tamper tests: flipped byte, swapped row_id, lower version, wrong key_version → all rejected

CREATE SEQUENCE blob_seq;
CREATE TABLE blobs (
  account_id uuid NOT NULL REFERENCES accounts ON DELETE CASCADE,
  row_id uuid NOT NULL,
  version int NOT NULL,
  seq bigint NOT NULL DEFAULT nextval('blob_seq'),   -- re-assigned on EVERY write
  key_version int NOT NULL,
  envelope bytea,                         -- NULL when deleted
  deleted boolean NOT NULL DEFAULT false,
  updated_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (account_id, row_id)
);
CREATE INDEX blobs_pull ON blobs (account_id, seq);
CREATE TABLE leases (
  account_id uuid NOT NULL REFERENCES accounts ON DELETE CASCADE,
  lease_key bytea NOT NULL,               -- HMAC-SHA256(lease_key, ...) — server can't invert
  holder_device_id uuid NOT NULL, priority smallint NOT NULL,
  state text NOT NULL CHECK (state IN ('held','done')),
  expires_at timestamptz NOT NULL,
  PRIMARY KEY (account_id, lease_key)
);

Write path (single statement, optimistic): UPDATE blobs SET version=version+1, seq=nextval('blob_seq'), envelope=$env, key_version=$kv, deleted=false, updated_at=now() WHERE account_id=$a AND row_id=$r AND version=$base RETURNING version, seq; zero rows → if row exists return 409 with current, else (base=0) INSERT … version=1 with ON CONFLICT DO NOTHING → 409 on conflict. Clear metadata in Neon is exactly: account UUID, handle, salt, params, verifier, wraps, device UUID + priority, row UUIDs, versions, seq, key_version, deleted flag, timestamps, lease hashes. H4 · Dedupe, change detection, completion


Same window twice: any overlap between new evidence event IDs and an existing agreement's covered_event_ids with same obligor+obligee → treat as update of that agreement.

Same room, different words: same obligor/obligee pair, same kind, amounts equal (or both null), due within ±2 days → merge into existing as an update suggestion.

Cross-room / cross-network: never auto-merge. Set flags.possible_duplicate_of → UI “Looks like the same as …” with Merge / Keep both.

Change: field-by-field diff of normalised values → one timeline event per changed field (term_change_suggested, pending:true) → banner on card “Maya changed the date to Monday — Apply / Ignore”.

Completion: “sent”, “paid”, “done”, Venmo/CashApp/Zelle mention, “got it thanks” → complete op → pill “Mark as done?” (never auto-done). paid_text with a smaller amount → payment_partial timeline event; remaining = amount − paid shown, obligation stays open.

Cancellation: “nvm”, “never mind”, “can't anymore”, “cancel” → cancel suggestion.

Dispute: two parties assert contradicting values in later messages → lifecycle=disputed suggestion with both quotes.

WHEN: launch, foreground, every 30 s while foreground, 2 s after a local write (debounced), after Matrix
      sync produced new agreements; Mac also every 60 s in background; iOS via BGAppRefreshTask.

J2 · Merge rules (deterministic, shared fixture file)


accepted/dismissed (user) beats suggested (AI) on review_state.

Delete (tombstone) beats edit. The editing device shows “Deleted on another device” with Restore (recreates with a new row_id).

Field-level 3-way merge using the last common version kept in the outbox: non-conflicting fields from both sides; same field changed on both → the side whose change is a user_edit wins over AI; both user → server version wins and the losing value is kept as a timeline event “Edited on another device: was X”.

Timeline and evidence arrays: union by id, sorted by at.

covered_event_ids: union.


J3 · Extraction leases (fixes A5)

lease_key = HMAC-SHA256(lease_key, room_id + "|" + last_event_id_in_window)    // server sees 32 opaque bytes
priority  = Mac 4 · iPad (Tier A) 3 · iPhone 2 · Web 1
wait      = Mac 0 s · iPad 10 s · iPhone 45 s · Web 90 s  (after the window trigger, before acquiring)
acquire(ttl 180 s) → granted → run pipeline → push blob → complete
                   → not granted, held → mark messages "leased"; when the holder's blob arrives the
                     covered_event_ids remove them; if TTL passes with no blob → retry acquire
                   → state done → skip

The keyed HMAC is deterministic for your devices but unguessable for Neon (it doesn't have the key), so it doesn't break the “no deterministic IDs linkable to messages” rule. It leaks only “two devices processed the same window”.

J4 · Messages plane vs derived plane


Messages: Matrix only. Each device syncs Matrix itself. Never in Neon.

Derived (agreements, settings, dismiss markers, device info): Neon ciphertext.

Web: IndexedDB stores {row_id, version, envelope} only plus an encrypted Matrix sync cache (envelopes under token_key); plaintext lives in memory. One tab is sync leader (Web Locks API); others listen on BroadcastChannel. Lock state shared across tabs.

Two-device test: iPad extracts → Mac shows the same agreement within 35 s, Mac's pipeline logs “lease held / covered”, zero duplicate rows
Offline edit on both devices → reconnect → merge fixture outcomes match exactly

L4 · AGENTS.md (paste verbatim into the repo)

You are one agent in a swarm building Relay. The spec in docs/spec.html is the contract.
1. Stay inside the folders your workstream owns. Need a change elsewhere? Write CONTRACT_CHANGE.md
   in your PR describing it; do not edit another workstream's files.
2. Schemas, prompts, copy and tokens change only via WS0 (human-approved). Never hand-edit generated code.
3. Never log message text, quotes, names, amounts, tokens or keys. Use os_log privacy .private / no console in prod.
4. Never put secrets in code. Server env only. Clients never call LLM providers directly.
5. Never add: briefs/recaps/summaries/digests, Ollama or any localhost LLM server, plaintext data in Neon,
   auto-send, auto contact merge, sentiment scoring, bbctl/Beeper integration (v2).
6. Every PR: tests for your rows in Part K, fixtures green in both languages where shared, builds for
   iOS + macOS + web. MLX code must also compile for Simulator (MockLLM path).
7. Use the Fake implementations of other workstreams until theirs merge. Don't block.
8. Follow the motion/copy/token tables exactly; no ad-hoc colours, durations or strings.
9. If the spec is ambiguous, pick the most conservative behaviour (ask the user, show "Not stated",
   never invent), note it in DECISIONS.md, and continue.
10. Commit small; main must always build. Feature flags in FeatureFlags.swift / flags.ts for unfinished UI.
